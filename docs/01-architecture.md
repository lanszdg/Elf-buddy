# Elf Buddy 架构设计（模块边界）

版本：v0.1（2026-10-10）｜状态：早期设计基线。当前实现和启动方式见 [README](../README.md)。

---

## 1. 产品定义

**Elf Buddy 是一个 PC 桌面常驻的"可成长兴趣搭子" AI 精灵。**

- 目标用户：被工作占满、有兴趣爱好但没有精力主动搜索/关注的人群。
- 核心价值：AI 主动理解兴趣、主动在恰当时机把内容送到用户面前。**AI 完成 80% 的工作，用户只做 20% 的回应**（"嗯"、"讲讲"、"换一个"）。
- 产品本体是精灵，不是 App。App 只是精灵的"家"（设置/日记/纠偏），约占 1% 的使用场景；99% 的相处发生在桌面与对话中。

### 已决策（Discussions 结论，不再讨论）

| # | 决策 | 依据 |
|---|---|---|
| D1 | PC 桌宠首发，移动端后置 | "工作间隙疲惫"核心场景发生在电脑前；移动端无在场概念，通道塌缩为推送 |
| D2 | push 而非 pull，无信息流/无内容列表页 | 用户洞察：有诉求、没精力主动使用 |
| D3 | 兴趣主导；热点可开关且占比 ≤30% | 用户明确要求 |
| D4 | 成长系统只做加法，绝不回退；无日常任务、无断签惩罚 | Replika 成长回退信任崩塌；MMO 打卡化软流失教训 |
| D7 | 组合开源创新，不从零造；自研仅限 3 个核心 | 见第 4 节模块映射 |
| D8 | 成长可视化 = 通过精灵言行自然流露（"我记得/我发现/我学了"），不做需要用户点进去看的花园/图鉴页面 | 用户明确修正 |

### 待验证假设（MVP 要回答的问题）

| # | 假设 | 验证指标 |
|---|---|---|
| H1 | 间隙主动搭话被接受而非被嫌烦 | L3 开口命中率（看完/追问比例）> 基线 |
| H2 | L2"显眼化"通道（做动作不出声）可爱而非打扰 | L2 点击率、负反馈率 |
| H3 | 人格化讲述 vs 新闻列表的留存差 | 30 日留存 A/B |
| H4 | "从看到做"是差异化价值 | 行动建议转化率 |
| H5 | 关系形成信号 | 用户主动向精灵分享/教精灵的频率；"换一只新精灵你愿意吗"抗拒度 |

## 3. 模块边界

### M1 在场层 Presence（elf-shell 内）

**职责**：精灵的"身体"。形象渲染、动画状态机、对话气泡、语音播报与接听、L2 显眼化动作。

**边界**：不做任何决策。收到 `SpeakCommand` 才表现；用户交互事件原样上报 elf-brain。不接触内容数据，不存记忆。

| 项 | 内容 |
|---|---|
| 开源基础（实装） | Electron 透明无边框窗口 + 点击穿透；**形象为程序生成精灵**（Canvas 参数化绘制：颜色/眼睛/装饰/尺寸，`sprite_config` 即捏脸参数），不引入 Live2D 运行时（Cubism 授权/体积/动作资产均不适配 MVP） |
| 语音（实装） | 唤醒词 + ASR：sherpa-onnx **在 brain 侧**（Python 绑定成熟；音频只走 127.0.0.1 环回，隐私等价）；TTS：壳侧系统 `speechSynthesis`（CosyVoice2 的 PyTorch 级体积破便携红线） |
| 明确不做 | 不做 Live2D 精修/3D；不 fork open-llm-vtuber（已半停更，仅参考其后端管线） |
| 形象定制（实装） | 引导页/设置面板捏脸（颜色/眼睛/装饰/尺寸）→ `POST /v1/profile` 的 `sprite_config` 落盘 → 壳侧 `setModel` 即时重绘；文生图立绘+表情差分（v0.1 设想）未实装 |

### M2 感知层 Perception（elf-shell 采集，elf-brain 维护状态机）

**职责**：回答"用户现在处于什么状态"。输出 6 态状态机变更事件。

**状态机**：`DEEP_WORK`（键鼠活跃+工作应用）/ `BUSY`（会议/演示全屏）/ `TRANSITION`（静默 10s–3min，刚停下手，**黄金窗口**）/ `IDLE`（长时静默刷网页）/ `AWAY`（锁屏）/ `DND`（深夜时段/用户手动）

| 项 | 内容 |
|---|---|
| 信号源（MVP） | `powerMonitor.getSystemIdleTime()`（空闲秒数）、`active-win`（前台应用+窗口标题）、会议进程检测（Zoom/Teams/腾讯会议进程 + 麦克风占用）、屏幕锁定、时段 |
| 信号源（进阶，后置） | screenpipe（事件驱动屏幕理解；注意 2026-06 起 source-available，商用需授权，MVP 不用） |
| 抑制规则 | 借鉴 opencode-alert：前台焦点抑制、quietHours 跨夜安静时段 |
| 明确不做 | 不做摄像头表情/情绪识别（隐私红线，默认永不开启） |

### M3 时机引擎 Timing Engine（elf-brain，**自研核心①**）

**职责**：回答"此刻说不说、说什么、用什么强度说"。是整个记忆/成长系统的**执行末端**——记忆层的所有积累在此变现。

**决策输出 = 通道分级（非二值）**：

| 通道 | 行为 | 门槛 |
|---|---|---|
| L3 主动开口 | 弹气泡/语音："歇会儿？有个事你肯定想听" | 最高：高价值 × TRANSITION/IDLE |
| L2 显眼化 | 做动作吸引注意（举手/蹦/举牌），不出声；决定权留给用户 | 中：值得说但时机一般 |
| L1 静默持有 | 用户主动凑过来时才说："你来了，正好有个事" | 低但有价值 |
| L0 憋着 | 不说，流入次日晨报/日记 | 兜底 |

**决策评分**（白盒规则 + 可学习参数，不用大模型做实时决策，不上 RL）：

```
speak_score = content_value(兴趣温度 × 匹配度)
              × state_factor(用户状态)
              × timing_factor(个人时机系数)
              - disturbance_cost(今日已打扰次数的递增惩罚)
              × trust_factor(关系账户命中率)
```

**硬规则**：
- 每日 L3 硬配额（冷启动 ≤3，随信任浮动）；一次只说一件事（多候选竞争取最高分）
- BUSY/全屏/深夜/用户说"别烦我" → 无条件静默；连续 2 次无视 → 当日禁 L3
- 预约类内容（直播/发布会/更新）走**定时任务通道**（用户定规则），不参与实时打扰判断
- L0 内容不丢弃，流入次日晨报

**唤醒调度 = 三层驱动**（2026-10 增补：STEPS 自触发思想，RecSys 2026 Oral，抖音10亿用户验证）：
1. **状态驱动**：用户状态机变更（进入 TRANSITION/IDLE）→ 立即重评想说清单
2. **周期巡逻**：低频兜底（借鉴 OpenClaw 心跳：活跃时段约束+状态去重+轮巡降本）
3. **价值自触发**：决策时同时计算"下一次最佳评估时机"并自主排程——想说清单中有高时效内容（urgency 衰减快 / scheduled_at 临近）时，引擎主动安排自己在价值峰值前醒来（如"20:00 剧集更新"→ 19:55 自唤醒查状态），不依赖状态变化或巡逻周期碰巧撞上。MVP 可简化为：入队时若 `urgency.not_after - now < 巡逻周期`，则按 not_after 设一次性自唤醒定时器。

| 项 | 内容 |
|---|---|
| 借鉴出处 | OpenClaw 心跳四件套（静默 ACK 抑制 / activeHours / 状态文件去重 / 轮巡降本）；Hermes `notify_on_complete`（事件驱动开口，不轮询）与"按真实活动而非时钟判空闲"；Meta ISM 四状态（开口/持续相关/无关静默/**去重静默**——已报过的事件不再烦用户）；Novu digest（重要立即说，次要攒批进晨报） |
| 冷启动 | 保守人格：日 ≤3 次、前两周以 L1/L2 为主攒反馈；onboarding 让用户选"活泼/安静"粗调初始值 |
| 学术背书 | AHs'26 实验：判断可打扰度时，喂用户历史自评/反馈记录提升最大 → 关系账户路线 |

### M4 记忆/成长底座 Memory（elf-brain，组装零自研）

**职责**：四层记忆，回答"这个用户是谁、爱什么、现在还在爱吗"。

| 层 | 内容 | 存储 |
|---|---|---|
| L0 情景流 | 全部交互/反馈/感知事件，append-only | SQLite + sqlite-vec |
| L1 原子事实 | 抽取的事实，带时间戳+置信度+来源+有效期（"正在追的剧"会完结） | Graphiti 时态边 |
| L2 兴趣图谱 | 领域→话题→实体；节点/边带**温度**（近期交互频率的衰减函数）与时态（valid_at/invalid_at，失效归档而非覆盖） | Graphiti（FalkorDB 嵌入式优先，Neo4j 备选） |
| L3 消费画像 | 怎么消费：短/长、吐槽/深度、何时有耐心；时机偏好 | 画像服务（见下） |

| 项 | 内容 |
|---|---|
| 图谱引擎 | Graphiti（getzep/graphiti，Apache-2.0）：双时态知识图谱，episode 溯源，向量+BM25+图遍历混合检索；温度/置信度作自定义边属性叠加 |
| 用户画像 | Honcho（Peer/Session/Message 原语 + 后台异步推理）。**风险：AGPL-3.0**，MVP 阶段作为设计参考 + 本地原型，商业化前需授权或以自研画像槽位替换 |
| 技能沉淀 | Hermes 模式：Markdown 技能文件（遵循 agentskills.io 开放标准）+ Curator 后台打分/合并/归档；离线进化用 DSPy/GEPA（20–100 条样本即可）。搭子的"技能"= 选题/讲述/时机策略参数，不是工具调用 |
| 人格系统 | 人设文件（性格/口癖）+ **立场记忆库**（发表过的看法入库，生成前检索校验一致性；上周吐槽过的导演这周不能夸）+ 精灵自身兴趣倾向（与用户重合→共鸣，不重合→碰撞/"索取"） |
| 成长呈现 | 通过言行流露（"我记得/我发现/我专门去补了课"）；每周成长汇报由 Review 管线生成 diff，精灵亲口说出；精灵日记每日自动生成，由精灵主动给用户看，不做独立页面 |

### M5 反馈学习闭环 Feedback Loop（elf-brain，**自研核心②**）

**职责**：把隐式反馈变成学习信号，回流记忆底座与时机引擎参数。2026 年开源空白件，AHs'26 验证其有效性。

**信号梯度**（兴趣产品特有的富信号）：

```
跳过(负) → 点开(弱正) → 看完(中正) → 停留久/回看(强正)
→ 主动追问"还有呢?"(很强) → 反过来分享给精灵"你看这个!"(最强)
```

**回路**：反馈事件 → 带符号 episode 写入 Graphiti + 喂画像服务 → Review 管线定期分析 → 更新三类资产：
1. 兴趣图谱温度/画像槽位（懂你的更新）
2. 时机引擎系数（state_factor / timing_factor / 配额）（会挑时候的更新）
3. 技能文件（选题/讲述风格的策略参数）（表达的更新）

**信任记账**：每次开口记录命中/未命中 → 关系账户 → 调节开口门槛与配额；连续未命中自动进入"安静期"（降配额、禁 L3）并主动校准（"我最近是不是话太多了？"）。

### M6 内容管线 Content Pipeline（elf-brain）

**职责**：兴趣雷达。抓取 → 清洗打标 → 入内容库 → 生成候选与讲述。

| 项 | 内容 |
|---|---|
| 抓取 | RSSHub 自建实例（5000+ 路由）；源适配器模式借鉴 newsnow（TypeScript，与 Electron 同栈，可内嵌） |
| 打标 | 便宜模型：领域/实体/质量分/情绪/时效类型（限时/常青） |
| 讲述生成 | 强模型：精灵视角转述——带立场、带连续记忆引用（"上周那个导演的新片翻车了"）、**可解释**（必带"给你看这个是因为…"）；生成前检索立场记忆库校验一致性 |
| 热点约束 | 热点源单独打标，经"和你有关"过滤器（明天同事聊到你想不想接上话）；日占比硬上限 ≤30%，可整体关闭 |
| 深度件 | 专题盘点（周末）、"从看到做"行动方案（教程路径/清单/日程建议） |
| 明确不做 | 不做无限信息流；每日精选候选有上限，宁缺毋滥——没好内容那天精灵说"今天你的领域没什么值得说的" |

### M7 匹配引擎 Match Engine（elf-brain，**自研核心③**）

**职责**：兴趣图谱 × 内容库的白盒匹配。2026 年无统治级开源件，是"懂你"的核心，握在自己手里。

- 粗排：内容 embedding × 兴趣节点 embedding（含温度加权）
- 精排：LLM 对 top-K 打分并生成匹配理由（即可解释性的来源，存入候选条目）
- 匹配分数是时机引擎 `content_value` 的主要输入

### M8 后台 Review 管线（elf-brain，低频任务）

**职责**：Learning Loop 的"评估+沉淀+再部署"。每晚/每周运行，**必须用便宜模型**，这是烧死小龙虾的成本红线。

- 反馈分析 → 更新时机系数与画像槽位（M5 的定期任务）
- 技能复盘 → 新技能入库/旧技能归档（Hermes 双链路变体）
- 记忆巩固：去重/抽象/过期清理（事实有效期管理）
- 生成：精灵日记、每周成长汇报（新增记忆/更新理解的 diff 人格化）、晨报

## 5. 进程与部署

- `elf-shell`：Electron 应用，Windows 优先（macOS 穿透/置顶限制多，后置）；打包为 portable（免安装，双击即用，无终端窗口）。
- `elf-brain`：本地 Python 进程，随 shell 启动拉起（PyInstaller onefile exe）；全部数据本地存储（生产 = Electron `userData/data/`，即 `%APPDATA%/<app>/data/`，壳经 `ELF_DATA_DIR` 传入），本地优先，无账号体系（MVP）。
- 进程间通信（实装）：`127.0.0.1:8787` + `/v1` 前缀；上行 HTTP（事件/查询），下行 WebSocket `ws://127.0.0.1:8787/v1/ws/shell`，语音 `…/v1/ws/voice`；一次性 token 经 `ELF_TOKEN` 环境变量传入（HTTP 头 / WS 查询参数），详见 `03-interfaces.md`。
- LLM：统一调用层封装多 provider；打标/抽取/巩固用便宜模型，讲述/复盘用强模型。单用户日 token 成本纳入 Review 管线监控。
